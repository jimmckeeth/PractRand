# Installation Guide

## 1. Configuring PractRand

The file `include/PractRand/config.h` contains PractRand's configuration. Depending upon your platform and compiler, you may need to edit it. It includes comments that describe available options.

## 2. Building PractRand

PractRand is intended to be built as a static library.
- It comes with an MSVC solution file.
- It does **NOT** come with build files for `make` / `autoconf` / etc.

If you cannot use the MSVC project file, you will need to manually compile and link all `.cpp` files in the PractRand `src/` directory and all of its subdirectories recursively. At the moment, that includes:
- `src/*.cpp`
- `src/RNGs/*.cpp`
- `src/RNGs/other/*.cpp`

### Building on Linux

To build the static library:
```bash
g++ -c src/*.cpp src/RNGs/*.cpp src/RNGs/other/*.cpp -O3 -Iinclude -Wno-constant-logical-operand
ar rcs PractRand.a *.o
```
*(Leftover `.o` files can be deleted afterwards)*

To build the PractRand command-line tools:
```bash
g++ -o RNG_test tools/RNG_test.cpp PractRand.a -O3 -Iinclude -Itools -pthread
g++ -o RNG_output tools/RNG_output.cpp PractRand.a -O3 -Iinclude -Itools -pthread
g++ -o RNG_benchmark tools/RNG_benchmark.cpp PractRand.a -O3 -Iinclude -Itools -pthread
```

### Building `RNG_to_TestU01`

Building `RNG_to_TestU01` is slightly more involved, since it must link with `PractRand.a` as well as TestU01 libraries:
- `libtestu01.a`
- `libmylib.a`
- `libprobdist.a`

Each of these libraries is generated by TestU01's build process.

## 3. Linking with PractRand

Linking is the same as for any other static library on your compiler. You may want the library file's name to start with `lib` (e.g. `libPractRand.a`) depending on your platform and linker preferences.
